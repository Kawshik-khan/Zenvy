# Zenvy - Security Assessment Report

## Executive Summary
This report details the security assessment of the Zenvy project, a Next.js-based communication application. The assessment was conducted following the AEGIS-X13 framework, covering attack surface discovery, threat modeling, and secure code review.

**Overall Risk Score: 45/100 (Medium)**

### Key Findings
- **Hardcoded Secrets**: The `.env` file contains production-grade credentials (Database, LiveKit, Upstash).
- **Disabled Security Controls**: Email verification is currently disabled in the authentication flow.
- **Missing Web Security Headers**: The application lacks a Content Security Policy (CSP).
- **Authorization Gaps**: Group and Channel joining logic relies solely on knowledge of the resource ID.

---

## Technical Findings

### [Finding-001] Hardcoded Secrets in Environment File
- **Severity**: Critical (as a practice) / Medium (local context)
- **Confidence**: High
- **CWE**: CWE-798: Use of Hardcoded Credentials
- **Impact**: Exposure of database and third-party API keys could lead to total data breach or service abuse.
- **Evidence**: `.env` file contains `DATABASE_URL`, `LIVEKIT_API_SECRET`, and `UPSTASH_REDIS_REST_TOKEN`.
- **Remediation**: Ensure `.env` is never committed to version control (verified ignored in `.gitignore`). Use a secret manager (e.g., Vercel Secrets, AWS Secrets Manager) for production.

### [Finding-002] Disabled Email Verification
- **Severity**: Medium
- **Confidence**: High
- **CWE**: CWE-304: Missing Critical Step in Authentication
- **Impact**: Allows malicious actors to register accounts with fake or stolen emails, increasing the risk of spam and account takeover.
- **Evidence**: `auth.ts` lines 63-66 show email verification logic is commented out.
- **Remediation**: Re-enable email verification once the email service (Resend) is configured.

### [Finding-003] Missing Content Security Policy (CSP)
- **Severity**: Medium
- **Confidence**: High
- **OWASP**: A03:2021-Injection
- **Impact**: Increases vulnerability to Cross-Site Scripting (XSS) and data injection attacks.
- **Evidence**: `next.config.ts` defines several security headers but omits `Content-Security-Policy`.
- **Remediation**: Implement a robust CSP in `next.config.ts` or via middleware.

### [Finding-004] Weak Join Authorization for Channels and Groups
- **Severity**: Low
- **Confidence**: Medium
- **Impact**: Any authenticated user can join any channel or group if they guess or obtain the UUID.
- **Evidence**: `app/actions/channel.ts` and `app/actions/group.ts` do not check for "private" status or invite requirements in the `join` actions.
- **Remediation**: Implement a "private" flag for groups/channels and require an invite or approval for joining.

---

## Attack Path Analysis
1. **Initial Access**: Attacker registers a fake account (due to disabled email verification).
2. **Discovery**: Attacker uses the `people-search` API to find user IDs and unique IDs.
3. **Exploitation**: Attacker guesses or leaks a `channelId` and joins a sensitive discussion without authorization.

---

## Remediation Roadmap

### Immediate (0–7 Days)
- Rotate all secrets found in `.env` if they have ever been shared or exposed.
- Implement a basic Content Security Policy (CSP).

### Short-Term (7–30 Days)
- Re-enable email verification.
- Add "Private" group/channel functionality to prevent unauthorized joining.

### Medium-Term (30–90 Days)
- Configure a TURN server for WebRTC to prevent IP leakage during P2P calls.
- Implement more granular RBAC (Role-Based Access Control) for group resources.
